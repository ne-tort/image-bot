# Архитектура

## Слои

```
tgbot  (aiogram)      ← единственный слой, знающий про Telegram
  └─ flows, handlers, ui

core   (чистый домен) ← ничего не знает про Telegram
  ├─ types            язык домена: Request, Media, Quota
  ├─ providers        адаптеры к API генерации (Pollinations, …)
  ├─ image/text/video/tts services   сценарии по модальностям
  ├─ prompting        стили, улучшение промптов
  ├─ mcp              текстовый ИИ → инструменты (генерация, правка, enhance)
  ├─ ratelimit        свои квоты — до провайдера
  ├─ storage          SQLite (aiosqlite), протокол в первую очередь
  └─ i18n             ru/en, единый тон
```

## Правила (проверяются на ревью)

1. **aiogram в core запрещён.** Нужен контекст чата — передаются
   `user_id`/`chat_id` как int, не объекты Telegram.
2. **HTTP в tgbot запрещён.** Хендлеры зовут сервисы `CoreContainer`
   и никогда не импортируют `httpx` и классы провайдеров.
3. **Одна точка композиции.** `CoreContainer` — единственное место склейки
   провайдера, хранилища и лимитов. Остальное получает зависимости (SOLID-D).
4. **Протоколы важнее классов.** `Storage` и `MediaProvider` —
   `typing.Protocol`: реализации меняются без правок потребителей.

## Зачем так

- Переиспользование: то же ядро завтра поведёт Discord/HTTP-интерфейс без правок.
- Тестируемость: сервисы проверяются на in-memory фейках протоколов.
- Частая смена провайдеров: адаптеры изолированы в `providers/`.
